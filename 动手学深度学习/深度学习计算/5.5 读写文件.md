# 读写文件（File I/O & Model Persistence）

在实际工业研发与学术研究中，训练一个深度学习模型往往需要耗费数小时、数天乃至数月的昂贵算力：
* **容灾备份（Fault Tolerance）**：服务器可能因突发断电、抢占式云实例（Spot Instances）回收或硬件故障而中断，定期保存中间检查点（Checkpoint）是防止算力浪费的生命线；
* **早停机制（Early Stopping）**：在验证集性能达到峰值时将最优权重持久化到磁盘；
* **跨环境部署与推理**：将离线训练好的模型打包交付至生产集群、移动边缘设备或嵌入式芯片进行在线推断。

本节我们将系统掌握 PyTorch 中张量对象与模型状态字典（`state_dict`）的高效持久化方法，阐释“只存权重不存类定义”的工业解耦哲学，剖析跨设备加载（`map_location`）与子网络权重移植的实战技巧。

---

## 一、张量对象的读写（Tensor Serialization）

PyTorch 提供了 `torch.save` 与 `torch.load` 函数，底层基于 Python 的 `pickle` 协议并针对密集张量存储（连续字节流 Raw Byte Buffers）进行了极速优化。

### 1. 单个张量读写

```python
import torch
from torch import nn
from torch.nn import functional as F

# 创建一个一维张量并写入磁盘
x = torch.arange(4)
torch.save(x, 'x-file')

# 将数据从文件读取回内存
x2 = torch.load('x-file')
print("读取的单张量:", x2)
```

> [!example]- 运行输出
> ```text
> 读取的单张量: tensor([0, 1, 2, 3])
> ```

### 2. 张量列表与字典的序列化

对于多张量组合，可以直接将其封装为 Python 原生列表或字典一并写入：

```python
# 保存与读取张量列表
y = torch.zeros(4)
torch.save([x, y], 'x-files')
x_read, y_read = torch.load('x-files')
print("读取的张量列表:", x_read, y_read)

# 保存与读取字符串映射字典（状态字典的雏形）
mydict = {'x': x, 'y': y}
torch.save(mydict, 'mydict')
mydict_read = torch.load('mydict')
print("读取的字典键值:", mydict_read)
```

> [!example]- 运行输出
> ```text
> 读取的张量列表: tensor([0, 1, 2, 3]) tensor([0., 0., 0., 0.])
> 读取的字典键值: {'x': tensor([0, 1, 2, 3]), 'y': tensor([0., 0., 0., 0.])}
> ```

## 二、模型参数的加载与保存（state_dict 机制）

### 1. 架构与权重的解耦设计哲学

在面向对象编程中，一个模型对象包含两部分：
1. **静态代码逻辑（Architecture）**：Python 类定义、`forward` 前向传播控制流分支；
2. **动态数值状态（State）**：可学习权重、偏置与持久化缓冲区。

深度学习工程界的通用铁律是：**在磁盘上只持久化纯数值的状态字典（`state_dict`），严禁直接序列化整个模型对象**。

```
  ┌────────────────────────────────────────────────────────┐
  │  工业界规范持久化流程 (Architecture-State Decoupled)   │
  │                                                        │
  │  1. 存盘: torch.save(model.state_dict(), 'model.pth')   │
  │  2. 恢复:                                              │
  │     clone = ModelClass()  (通过清晰代码实例化拓扑结构)  │
  │     clone.load_state_dict(torch.load('model.pth'))     │
  │     clone.eval()          (固化评估模式)               │
  └────────────────────────────────────────────────────────┘
```

> [!important] 架构避坑：为什么严禁直接 `torch.save(net, 'model.pth')`？
> 直接保存整个网络对象（`torch.save(net, ...)`）虽然省去了重写网络实例化的两行代码，但具有极大的工程脆弱性：
> 1. **代码路径强耦合**：`pickle` 在序列化对象时并不保存 Python 类源码，而是保存模块路径引用（如 `__main__.MLP`）。一旦重构代码目录、重命名类名或在另一个工程库中导入，`torch.load` 会直接抛出 `AttributeError: Can't get attribute 'MLP' on <module>`！
> 2. **环境版本脆弱**：依赖 Python 解释器和 PyTorch 内部对象的私有字段，跨版本兼容性极差。
> 3. **安全隐患**：反序列化任意 Python 对象存在任意代码执行漏洞。现代 PyTorch 推荐使用 `torch.load(..., weights_only=True)` 严格限制只允许加载纯张量数据。

### 2. 标准工程流程闭环验证

```python
class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.hidden = nn.Linear(20, 256)
        self.output = nn.Linear(256, 10)

    def forward(self, x):
        return self.output(F.relu(self.hidden(x)))

# 实例化并执行一次基准推断
net = MLP()
X = torch.randn(size=(2, 20))
Y = net(X)

# 1. 导出状态字典到磁盘
torch.save(net.state_dict(), 'mlp.params')

# 2. 从零实例化一个全新对象（此时参数为随机初始化）
clone = MLP()

# 3. 将磁盘中的权重无缝注入新网络
clone.load_state_dict(torch.load('mlp.params'))

# 4. 切换为评估模式
clone.eval()

# 5. 健全性验证：两组输出必须精确一致
Y_clone = clone(X)
print("克隆模型与原模型输出是否逐元素绝对相等:", bool((Y_clone == Y).all()))
```

> [!example]- 运行输出
> ```text
> 克隆模型与原模型输出是否逐元素绝对相等: True
> ```

> [!tip] 关键工程细节：为什么加载完权重后必须显式调用 `clone.eval()`？
> 网络中的某些高级层在**训练（Training）**与**评估（Inference）**时的数学行为完全不同：
> * **`nn.Dropout`**：训练时按概率 $p$ 随机置零神经元，评估模式下关闭丢弃并保持原值；
> * **`nn.BatchNorm2d`**：训练时使用当前 Batch 的实时均值与方差，评估模式下冻结并切换使用训练全周期的移动滑动均值（Running Mean/Var）。
> 
> 若遗漏 `clone.eval()`，测试数据将继续扰乱 BatchNorm 统计量并触发随机 Dropout，导致推理结果严重劣化！

## 三、工业级完整检查点（Checkpoint）设计规范

在生产级大型模型训练中，仅保存 `model.state_dict()` 是远远不够的。如果训练中断需要断点续训，必须保存**完整的系统状态快照**：

```python
checkpoint = {
    'epoch': 45,
    'model_state_dict': net.state_dict(),
    'optimizer_state_dict': optimizer.state_dict(),  # 保存动量、二阶梯度累加器
    'scheduler_state_dict': lr_scheduler.state_dict(),# 保存当前学习率衰减步数
    'best_metric': 0.942,                             # 历史最优验证集指标
}
torch.save(checkpoint, 'checkpoint_epoch_45.pt')
```

恢复断点续训时：
```python
checkpoint = torch.load('checkpoint_epoch_45.pt', map_location='cpu')
net.load_state_dict(checkpoint['model_state_dict'])
optimizer.load_state_dict(checkpoint['optimizer_state_dict'])
lr_scheduler.load_state_dict(checkpoint['scheduler_state_dict'])
start_epoch = checkpoint['epoch'] + 1
```

## 四、跨设备加载（`map_location` 机制）

一个极为高频的工业场景是：**在 GPU 集群上训练保存的模型，需要部署到仅有 CPU 的推断服务器上，或者加载到不同卡号的 GPU 上**。

默认情况下，`torch.load` 会尝试将张量反序列化到当初保存它的原设备（例如 `cuda:0`）。若目标机器没有 GPU，会直接报 `RuntimeError: CUDA error: no kernel image is available`。

PyTorch 提供了 `map_location` 参数实现硬件设备地址的动态重定向：

```python
# 场景 1: 将 GPU 训练的模型权重无缝加载到 CPU
state_dict = torch.load('mlp.params', map_location=torch.device('cpu'))

# 场景 2: 将卡号为 cuda:0 的权重动态映射到 cuda:1
state_dict = torch.load('mlp.params', map_location={'cuda:0': 'cuda:1'})
```

---

## 五、小结

1. **`torch.save` / `torch.load`**：提供底层连续内存张量的高性能序列化支持；
2. **解耦规范**：永远通过 `state_dict` 保存纯参数张量，通过可维护的 Python 代码恢复网络拓扑；
3. **推断一致性**：权重加载完毕后务必执行 `model.eval()` 冻结动态层；
4. **跨环境部署**：合理运用 `map_location` 处理异构硬件间的权重重映射。

## 六、课后练习详尽推导与代码实证

### 练习 1：即使不需要将经过训练的模型部署到不同的设备上，存储模型参数还有什么实际的好处？

**【深度工程剖析】**：
在同一个单机研发闭环中，参数持久化依然是核心基石：
1. **早停法（Early Stopping）恢复最优解**：随着 Epoch 增加，模型可能在第 50 轮过拟合，存储历史 Epoch 的权重能够确保实验结束时准确拉取验证集 Loss 最小或 Accuracy 最高的检查点，而不是最后一轮过拟合的权重；
2. **模型融合与集成学习（Model Ensemble & Model Soup）**：
   * 训练同一模型的多个不同随机种子版本，保存各版本参数后，可以在推理阶段进行软投票（Soft Voting）；
   * 最近的前沿技术（Model Soup / SWA）可以直接将多个不同收敛检查点的权重矩阵进行**算术平均**，零推理开销提升泛化能力；
3. **指数移动平均（EMA, Exponential Moving Average）权重管理**：在训练阶段额外维护一套平滑权重并持久化，专用于下游评估；
4. **超参数敏感度对比与实验溯源**：持久化权重后，可对同一个基础模型开展不同优化器、学习率调度或量化剪枝对比实验。

### 练习 2：假设我们只想复用网络的一部分，以将其合并到不同的网络架构中（例如在新网络中使用之前网络的前两层），该怎么做？

**【两种主流工业级解决方案】**：

#### 方案 A：子模块代码级移植（Sub-module Slicing）

如果原始网络是模块化设计的，直接将预训练网络的子层赋值给新网络对应的层：

```python
# 假设 pretrained_net 已经训练完毕
pretrained_net = nn.Sequential(
    nn.Linear(20, 64),  # 第 0 层
    nn.ReLU(),          # 第 1 层
    nn.Linear(64, 32),  # 第 2 层
    nn.Linear(32, 10)   # 第 3 层分类头
)

# 构建新网络：复用原网络前两层，并追加全新的分类头
new_net = nn.Sequential(
    pretrained_net[0],  # 直接引用第 0 层权重
    pretrained_net[1],  # ReLU
    pretrained_net[2],  # 第 2 层
    nn.Linear(32, 2)    # 全新下游二分类头
)

# 冻结移植层参数，仅微调新头 (Fine-tuning)
for param in new_net[:3].parameters():
    param.requires_grad = False

print("新网络结构:")
print(new_net)
```

> [!example]- 运行输出
> ```text
> 新网络结构:
> Sequential(
>   (0): Linear(in_features=20, out_features=64, bias=True)
>   (1): ReLU()
>   (2): Linear(in_features=64, out_features=32, bias=True)
>   (3): Linear(in_features=32, out_features=2, bias=True)
> )
> ```

#### 方案 B：基于 `strict=False` 的参数字典选择性注入

如果在新网络中层名称与原网络一致，可以通过过滤字典加载：

```python
# 读取预训练状态字典
pretrained_dict = torch.load('mlp.params', map_location='cpu')

class NewBackbone(nn.Module):
    def __init__(self):
        super().__init__()
        self.hidden = nn.Linear(20, 256) # 与 MLP 保持相同的名称 'hidden'
        self.new_head = nn.Linear(256, 2) # 全新分类头

    def forward(self, x):
        return self.new_head(F.relu(self.hidden(x)))

new_model = NewBackbone()
# strict=False 允许忽略不匹配的键值 (缺失或冗余)
incompatible_keys = new_model.load_state_dict(pretrained_dict, strict=False)
print("未匹配的键:", incompatible_keys)
```

> [!example]- 运行输出
> ```text
> 未匹配的键: _IncompatibleKeys(missing_keys=['new_head.weight', 'new_head.bias'], unexpected_keys=['output.weight', 'output.bias'])
> ```

### 练习 3：如何同时保存网络架构和参数？需要对架构加上什么限制？

**【架构与参数协同持久化的现代工业方案】**：

若必须将**计算图拓扑结构**与**物理权重张量**打包成脱离 Python 运行时的单一自包含二进制文件，主要有以下三种工业级标准：

1. **TorchScript (`torch.jit.trace` / `torch.jit.script`)**：
   * **原理**：将网络编译为 TorchScript 中间表示（IR），生成 `.pt` 文件；
   * **施加的架构限制**：
     * 若使用 `trace` 追踪：前向传播中的 Python 动态控制流（如依赖张量数值的 `if/while` 循环）会被展开并硬编码为静态图，丧失动态条件分支；
     * 若使用 `script` 编译：Python 代码必须遵守 TorchScript 的严格静态类型子集（禁止使用任意外部第三方库，动态列表需限定元素类型）。

2. **ONNX（Open Neural Network Exchange）标准**：
   * **原理**：转换为跨语言、跨框架的通用计算图规范，利用 `torch.onnx.export` 导出；
   * **施加的架构限制**：所有微观算子必须存在于 ONNX 官方算子集（Opset）中。高度定制的动态非标算子必须编写自定义 C++ ONNX 映射插件。

3. **Safetensors 规范（HuggingFace 行业新标准）**：
   * **原理**：专门解决传统 pickle 协议的安全漏洞，采用零内存拷贝（Zero-Copy Memory-Mapped I/O）技术；
   * **限制**：只包含张量数据与其元数据头（JSON 字典），完全剔除可执行代码，天生防止恶意反序列化代码注入。

# softmax回归的简洁实现

在 [[3.3 线性回归的简洁实现|3.3 节 (线性回归简洁实现)]]中，
我们发现**通过深度学习框架的高级API能够使实现线性回归变得更加容易**。
同样，通过深度学习框架的高级API也能更方便地实现softmax回归模型。
本节如在 [[3.6 softmax回归的从零开始实现|3.6 节 (softmax从零实现)]]中一样，
继续使用Fashion-MNIST数据集，并保持批量大小为256。

```python
import torch
from torch import nn
from d2l import torch as d2l
```

```python
batch_size = 256
train_iter, test_iter = d2l.load_data_fashion_mnist(batch_size)
```

## 初始化模型参数

如我们在 [[3.4 softmax回归|3.4 节 (softmax回归)]]所述，
**softmax回归的输出层是一个全连接层**。
因此，为了实现我们的模型，
我们只需在`Sequential`中添加一个带有10个输出的全连接层。
同样，在这里`Sequential`并不是必要的，
但它是实现深度模型的基础。
我们仍然以均值0和标准差0.01随机初始化权重。

```python
# PyTorch不会隐式地调整输入的形状。因此，
# 我们在线性层前定义了展平层（flatten），来调整网络输入的形状
net = nn.Sequential(nn.Flatten(), nn.Linear(784, 10))

def init_weights(m):
    if type(m) == nn.Linear:
        nn.init.normal_(m.weight, std=0.01)

net.apply(init_weights);
```

## 重新审视Softmax的实现

在前面 [[3.6 softmax回归的从零开始实现|3.6 节 (softmax从零实现)]]的例子中，
我们计算了模型的输出，然后将此输出送入交叉熵损失。
从数学上讲，这是一件完全合理的事情。
然而，从计算角度来看，指数可能会造成数值稳定性问题。

回想一下，softmax函数$\hat y_j = \frac{\exp(o_j)}{\sum_k \exp(o_k)}$，
其中$\hat y_j$是预测的概率分布。
$o_j$是未规范化的预测$\mathbf{o}$的第$j$个元素。
如果$o_k$中的一些数值非常大，
那么$\exp(o_k)$可能大于数据类型容许的最大数字，即*上溢*（overflow）。
这将使分母或分子变为`inf`（无穷大），
最后得到的是0、`inf`或`nan`（不是数字）的$\hat y_j$。
在这些情况下，我们无法得到一个明确定义的交叉熵值。

解决这个问题的一个技巧是：
在继续softmax计算之前，先从所有$o_k$中减去$\max(o_k)$。
这里可以看到每个$o_k$按常数进行的移动不会改变softmax的返回值：

$$
\begin{aligned}
\hat y_j & =  \frac{\exp(o_j - \max(o_k))\exp(\max(o_k))}{\sum_k \exp(o_k - \max(o_k))\exp(\max(o_k))} \\
& = \frac{\exp(o_j - \max(o_k))}{\sum_k \exp(o_k - \max(o_k))}.
\end{aligned}
$$

在减法和规范化步骤之后，可能有些$o_j - \max(o_k)$具有较大的负值。
由于精度受限，$\exp(o_j - \max(o_k))$将有接近零的值，即*下溢*（underflow）。
这些值可能会四舍五入为零，使$\hat y_j$为零，
并且使得$\log(\hat y_j)$的值为`-inf`。
反向传播几步后，我们可能会发现自己面对一屏幕可怕的`nan`结果。

尽管我们要计算指数函数，但我们最终在计算交叉熵损失时会取它们的对数。
通过将softmax和交叉熵结合在一起，可以避免反向传播过程中可能会困扰我们的数值稳定性问题。
如下面的等式所示，我们避免计算$\exp(o_j - \max(o_k))$，
而可以直接使用$o_j - \max(o_k)$，因为$\log(\exp(\cdot))$被抵消了。

$$
\begin{aligned}
\log{(\hat y_j)} & = \log\left( \frac{\exp(o_j - \max(o_k))}{\sum_k \exp(o_k - \max(o_k))}\right) \\
& = \log{(\exp(o_j - \max(o_k)))}-\log{\left( \sum_k \exp(o_k - \max(o_k)) \right)} \\
& = o_j - \max(o_k) -\log{\left( \sum_k \exp(o_k - \max(o_k)) \right)}.
\end{aligned}
$$

我们也希望保留传统的softmax函数，以备我们需要评估通过模型输出的概率。
但是，我们没有将softmax概率传递到损失函数中，
而是**在交叉熵损失函数中传递未规范化的预测，并同时计算softmax及其对数**，
这是一种类似["LogSumExp技巧"](https://en.wikipedia.org/wiki/LogSumExp)的聪明方式。

```python
loss = nn.CrossEntropyLoss(reduction='none')
```

## 优化算法

在这里，我们**使用学习率为0.1的小批量随机梯度下降作为优化算法**。
这与我们在线性回归例子中的相同，这说明了优化器的普适性。

```python
trainer = torch.optim.SGD(net.parameters(), lr=0.1)
```

## 训练

接下来我们**调用 [[3.6 softmax回归的从零开始实现|3.6 节 (softmax从零实现)]] 中定义的训练函数来训练模型**。

```python
num_epochs = 10
d2l.train_ch3(net, train_iter, test_iter, loss, num_epochs, trainer)
```

## 小结

* 使用深度学习框架的高级API，我们可以更简洁地实现softmax回归。
* 从计算的角度来看，实现softmax回归比较复杂。在许多情况下，深度学习框架在这些著名的技巧之外采取了额外的预防措施，来确保数值的稳定性。这使我们避免了在实践中从零开始编写模型时可能遇到的陷阱。

## 练习

### 📌 练习 1：超参数敏感度调优（Hyperparameter Tuning）

> **问题**：尝试调整超参数（例如批量大小 `batch_size`、迭代周期数 `num_epochs` 和学习率 `lr`），观察模型的收敛速度与最终精度变化。

**系统性调优机理与联动规律**：

1. **学习率 $\eta$（`lr`）的步长效应**：
   - 参数沿负梯度方向更新：$\mathbf{w} \leftarrow \mathbf{w} - \eta \nabla_{\mathbf{w}} L$。
   - `lr` 过小（如 $0.001$）：更新极其缓慢，在有限的 epoch 内无法逼近极小值谷底，产生欠拟合；
   - `lr` 适中（如 $0.1$）：损失平滑下跌，训练快速收敛；
   - `lr` 过大（如 $1.0$ 或 $5.0$）：单步跳跃过大越过局部极值点，引起振荡甚至发散（Loss 变成 `inf` 或 `NaN`）。
2. **批量大小 $B$（`batch_size`）的方差效应**：
   - 小批量梯度估计的方差满足 $\operatorname{Var}(\mathbf{g}_B) = \frac{\sigma^2}{B}$。
   - 小 Batch（如 $16$）：梯度随机噪声大，单步更新方向不稳定，但这种随机抖动在复杂非凸曲面上具有类似隐式正则化的探索效果，有助于跳出浅鞍点；缺点是无法充分利用 GPU 矩阵计算单元的高并发算力；
   - 大 Batch（如 $512$）：梯度方向非常稳定精确，硬件吞吐效率极高，但如果学习率未相应放大，收敛速度会显著放缓。
3. **核心联动理论：线性缩放法则（Linear Scaling Rule）**：
   - Facebook 提出经典经验准则：当批量大小扩大 $k$ 倍时，学习率也应当按比例放大 $k$ 倍：
     $$\text{若 } B' = k \cdot B \implies \eta' = k \cdot \eta$$
   - **理论依据**：在遍历相同样本总量前提下，大 Batch 的参数更新步数减少为原来的 $\frac{1}{k}$。为了使参数在经历相同数据量后的总位移保持相近，每一步的步长必须扩大 $k$ 倍。当 $B$ 极大时需配合学习率预热（Learning Rate Warmup）。

### 📌 练习 2：过拟合与长期训练精度停滞

> **问题**：大幅增加迭代周期的数量（如 50 轮以上）。为什么测试集精度会在达到峰值后逐渐停滞甚至出现下滑？这种现象叫什么？我们有哪些常规策略可以应对它？

**深度理论解析与应对策略**：

1. **现象定义：过拟合（Overfitting）与泛化差距**：
   - 随着训练轮次大幅增加，训练集损失 $\mathcal{L}_{\text{train}}$ 持续下降，训练精度逼近 $100\%$；但测试集损失 $\mathcal{L}_{\text{test}}$ 在达到最低点后开始向上反弹翘起，测试集精度停滞甚至出现下滑。
   - 这种在已知训练集拟合过好、而在未知测试集泛化性能退化的现象称为 **过拟合（Overfitting）**，两者表现之差称为 **泛化差距（Generalization Gap）**。
2. **数学与统计学根源**：
   - **经验风险最小化（ERM）拟合噪声**：训练过程以样本经验损失为优化目标。在训练后期，模型已经学完了宏观规律，为了让损失进一步趋向于 0，优化器开始强行学习训练集特有的采样偏差、图像局部微小瑕疵以及标签噪声等非本质虚假相关性（Spurious Correlation）。
   - **Softmax 权重无限膨胀（Overconfidence）**：交叉熵损失 $\ell = -\log(\hat{y}_y)$ 只有当真实类得分远大于其他类（$o_y - o_k \to +\infty$）时才接近 0。在无正则化约束下，模型倾向于无限放大权重矩阵范数 $\|\mathbf{W}\|$，导致模型输出变得极度过度自信，决策边界对输入的微小扰动异常脆弱。
3. **工业界 5 大标准防御策略**：
   - **早停法（Early Stopping）**：在验证集上实时监控性能，一旦验证集损失连续 $k$ 轮不再下降，立即终止训练并回滚保存最优检查点（Checkpoint）；
   - **权重衰减（$L_2$ 正则化）**：在损失函数中增加惩罚项 $\frac{\lambda}{2}\|\mathbf{w}\|_2^2$，遏制参数过度膨胀，强制学习平滑简单的边界（第 4 章 4.5 节）；
   - **暂退法（Dropout）**：训练期以固定概率随机失活部分神经元，打破特征间的共适应性（第 4 章 4.6 节）；
   - **数据增强（Data Augmentation）**：对输入图像施加随机平移、轻微旋转、翻转或裁剪，人为扩展有效样本分布，抑制记忆性拟合；
   - **学习率退火衰减（LR Decay）**：训练中后期逐步降低学习率，防止大步长更新破坏已找到的优质极小值区域。
